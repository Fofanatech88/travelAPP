# Core journeys

## First useful PTO result

Welcome → choose individual/group goal → choose year and calendar → enter workdays and PTO allowance/balance → confirm employer-observed holidays → choose duration/period and blackouts → calculate → inspect result and assumptions → share, save, or start a group trip.

Progressively disclose optional inputs while retaining the ability to revise all assumptions. Preserve form values after errors. Explain no-results with actionable adjustments; never invent a feasible window. Anonymous computation must work without Supabase credentials. Saving persistently or creating a trip can introduce authentication after value is delivered.

## Organizer reaches agreed dates

Sign in → create private draft → review invitation access and share → see response counts → generate options → inspect participation and PTO burden → request votes → select preferred window → collect confirmations and leave-approval states → explicitly confirm trip → share confirmed summary/calendar.

Show unanswered invitations separately from declines. Late availability changes invalidate affected options/confirmations and prompt review; they must not silently keep a false consensus. Cancelling requires an explicit action and visible cancelled status.

## Guest responds through a browser

Open newly generated invitation URL directly → see minimal trip context and privacy explanation → provide display name and availability/private constraints → review what is shared → submit → see acknowledgment and scoped response-edit mechanism → vote/confirm when allowed.

No installation or registration gate for basic availability. Expired/revoked links show a safe request-new-link state without leaking trip details. Native deep links must preserve destination context and offer browser fallback. Access to the URL alone must never reveal participants' private data.

## Returning user

Open dashboard → inspect requests needing action, upcoming/confirmed trips and saved opportunities → resume a relevant task. Empty states explain how to get started. Completed/cancelled history remains understandable without crowding the primary view. Replanning with previous groups is later roadmap work.
