# Roadmap

Phases are outcome gates, not date commitments. Use lightweight one-week cycles: select a small dependency-ready set, demonstrate actual behavior, record defects/debt and update priorities.

| Phase                        | Outcome gate                                                                                                    | Current status                    |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------- | --------------------------------- |
| 0 — Engineering organization | Durable operating contract, roles, architecture, product backlog, environment/test/cost strategy                | In progress: initialization       |
| 1 — App foundation           | Shared Expo welcome/navigation, tokens, safe configuration, CI and routing proof; verified limitations recorded | In progress: scaffold             |
| 2 — First vertical slice     | Account-free accurate PTO recommendation with explainable assumptions and meaningful edge tests                 | Not started; sprint plan prepared |
| 3 — Accounts and trips       | Users manage only their own trips and dashboard                                                                 | Not started                       |
| 4 — Invitations              | Secure guest browser participation and validated iOS linking                                                    | Not started                       |
| 5 — Group planning           | Private constraints produce feasible, fair and explainable options                                              | Not started                       |
| 6 — Agreement                | Voting, attendance/leave approval states, organizer confirmation and sharing                                    | Not started                       |
| 7 — Controlled beta          | Usability/accessibility/security regression, monitoring, privacy requirements and TestFlight readiness          | Not started                       |
| 8 — Public release           | Beta defects resolved, explicit founder release approval, App Store submission and monitoring                   | Not started                       |

After MVP: 1.1 private Trip Capsules and plan-again; 1.2 travel passport/recaps; 2 opt-in companion network only after approved safety systems; 3 authorized financial/rewards optimization. Premium subscriptions and partnerships require a separate business decision. No later capability is implicitly scheduled for implementation.

The immediate recommendation is to finish foundation verification and execute PTO-01/02/03 as the smallest useful slice, then shareability/annual allocation and accounts. Holiday source accuracy and dynamic invitation routing are early technical risks. Xcode/native toolchain and external account availability are tracked in the initialization/operations records rather than assumed complete.
